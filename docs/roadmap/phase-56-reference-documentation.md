# Phase 56: Reference Documentation From One Source

## Status: Planned

The website teaches the language, but it has no reference for the two things
a user looks up most: what an error code means, and what the standard library
offers. Both exist only in the compiler repository, and only in part:

- The compiler emits about 190 `E####` codes. `docs/language/diagnostics.md`
  lists ranges of them with a category each; no code has an example or a fix,
  and nothing checks the list against the compiler. Four lexer errors share
  their codes with parser errors (`E0003`–`E0006`).
- The standard library has ten modules with about 350 open declarations, each
  with a `"""` documentation block, and no tool that turns those blocks into
  pages. The website has no standard-library section.

Reference text that is copied by hand into the website goes out of date with
the next release. This phase makes the compiler repository the only source of
both references, checks them against the compiler, and builds the website
pages from them.

## Goals

1. **One registry of codes.** A `DiagnosticCode` type holds every code; every
   diagnostic is built from it. The four colliding lexer codes become
   `E0024`–`E0027` (ADR-0123).
2. **Catalog check first.** The test of ADR-0123 exists before the entries:
   every emitted code has an entry, every `fails=` example reports its code
   and every `compiles` block checks. Until all entries exist, the test lists
   the codes still missing instead of failing, and the list may only shrink.
3. **Catalog entries.** One entry per code under
   `docs/language/diagnostics/`, written range by range: lexer and parser,
   bindings and ownership, types and calls, structs, enums and generics,
   arrays and arenas, modules and visibility, tests and layout, strict policy.
   Each range lands with its examples verified, and the missing list reaches
   zero at the end of this goal.
4. **`actus explain`.** The command of ADR-0123, with the catalog embedded in
   the binary, and the closing `actus explain` line in the report of a failed
   `check`, `build`, `run` or `test`.
5. **`actus doc`.** A command that writes Markdown reference pages for a
   package: one page per module, from its facade and the `"""` blocks of what
   the facade opens, with each verb's signature, its ownership roles, its
   return type and the variants of its errors. It runs on the standard library
   and on any user project. An ADR fixes the output format and what a
   documentation block must contain to pass a strict check (every open
   declaration documented, every `Result` error variant named).
6. **Release assets.** The release archive or the repository at the release
   tag carries the generated catalog and standard-library pages, so the
   website can take the pages of the exact version it documents.
7. **Website.** Two new sections, "Error codes" and "Standard library",
   generated from the assets of goal 6 by a script in the website
   repository. The website does not keep its own copy of either text.

## Exit criteria

- The catalog test runs in the compiler's suite on every platform, with no
  missing entries, and has been seen failing for a missing entry, a wrong
  code in a `fails=` example and a `compiles` block that does not compile.
- `actus explain` prints every entry and rejects unknown codes; its tests cover
  both, and the closing line appears in the failed-command tests.
- `actus doc` documents every open declaration of the standard library, and its
  strict check passes on the standard library.
- The website shows both sections for the current release, regenerated by its
  release update without hand edits.
- `docs/language/diagnostics.md`, `docs/language/lexical-map.md` and the user
  guide name the new lexer codes and point to the catalog.
