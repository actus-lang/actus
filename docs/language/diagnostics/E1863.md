# E1863: stack_limit is not supported for this target

A `meta stack_limit` verb is accepted only when the selected backend can prove
the frame size of the final symbol for the build target (ADR-0103). Today the
LLVM backend proves it for `x86_64-unknown-linux-gnu` and
`thumbv7em-none-eabi`; the Cranelift backend proves it for no target. The
check needs only the target of `Actus.toml` and the backend, so `actus check`
reports it as well as `actus build` and `actus run`. The message names the
backend and the target, as in ``stack_limit proof is not supported by backend
`llvm` for target `aarch64-unknown-linux-gnu` ``. The error points at the verb
that carries the contract, in whichever module it is declared.

## Example

```actus fails=E1863
meta stack_limit(bytes: 256u32)
verb main() {
}
```

```toml file=Actus.toml
[package]
name = "example"
version = "0.1.0"
edition = "alpha"
entry = "main"

[build]
target = "aarch64-unknown-linux-gnu"
profile = "debug"
runtime = "std"
```

## Fix

Build for a target the backend proves, or remove the `meta stack_limit`
contract from the verb when the target cannot be changed.

```actus compiles file=src/main.act
meta stack_limit(bytes: 256u32)
verb main() {
}
```

```toml file=Actus.toml
[package]
name = "example"
version = "0.1.0"
edition = "alpha"
entry = "main"

[build]
target = "x86_64-unknown-linux-gnu"
profile = "debug"
runtime = "std"
```
