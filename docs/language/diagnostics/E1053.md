# E1053: wrong number of type arguments

A generic type or verb takes exactly the type arguments that its declaration
lists. `Box[T]` takes one, so `Box[Int, Int]` is rejected, and so is a type
argument given to something that is not generic. Missing and extra arguments
are both reported. The message names the declaration and says how many
arguments were expected and how many were found. The error points at the
statement that holds the type or the call.

## Example

```actus fails=E1053
struct Box[T] {
    erg item: T,
}

verb main() {
    erg b: Box[Int, Int] = Box[Int] { item: 1 };
}
```

```actus fails=E1053
verb identity(erg item: Int) -> Int {
    return item;
}

verb main() {
    erg v: Int = 1;
    erg x = identity[Int](item: v);
}
```

## Fix

Give exactly the arguments that the declaration lists. Remove the brackets at
a call of a verb that is not generic.

```actus compiles
struct Box[T] {
    erg item: T,
}

verb main() {
    erg b: Box[Int] = Box[Int] { item: 1 };
}
```

```actus compiles
verb identity(erg item: Int) -> Int {
    return item;
}

verb main() {
    erg v: Int = 1;
    erg x = identity(item: v);
}
```
