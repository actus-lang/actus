# E1100: module path cannot be resolved

An `import` names a module path that the compiler cannot turn into a module.
There are two causes. The path may have no usable form, such as `std` alone,
because a standard-library import names one module, as in `std::io`. Or the
path may start with `std` in a project that does not use the standard library.
Packages opt in with `runtime = "std"` under `[build]` in `Actus.toml`
(ADR-0050). The error points at the first line of the importing file.

## Example

```actus fails=E1100
import std;

verb main() {
}
```

```actus fails=E1100 file=src/main.act
import std::io;

verb main() {
}
```

```toml file=Actus.toml
[package]
name = "example"
version = "0.1.0"
edition = "alpha"
entry = "main"

[build]
target = "host"
profile = "debug"
runtime = "core"
```

## Fix

Import one standard-library module by its full path.

```actus compiles
import std::io;

verb main() {
}
```

When the path is right, select the standard library in `Actus.toml`.

```actus compiles file=src/main.act
import std::io;

verb main() {
}
```

```toml file=Actus.toml
[package]
name = "example"
version = "0.1.0"
edition = "alpha"
entry = "main"

[build]
target = "host"
profile = "debug"
runtime = "std"
```
