# E1138: constant arithmetic overflows its type

Integer arithmetic traps when the result does not fit the type of the operands
(ADR-0115). When both operands are literals, the compiler computes the result
itself and reports the overflow at compile time, instead of building a program
that is sure to trap. This holds for `+`, `-` and `*`, and for `/` when the
minimum value is divided by `-1`. The message names the operator and the type,
and suggests `+%` to wrap or `+|` to saturate.

## Example

```actus fails=E1138
verb main() {
    erg total: u8 = 200u8 + 100u8;
}
```

```actus fails=E1138
verb main() {
    erg quotient: i8 = -128i8 / -1i8;
}
```

## Fix

Use a wider type, a wrapping or saturating operator, or a value that fits.

```actus compiles
verb main() {
    erg total: u32 = 200u32 + 100u32;
    erg wrapped: u8 = 200u8 +% 100u8;
    erg saturated: u8 = 200u8 +| 100u8;
}
```
