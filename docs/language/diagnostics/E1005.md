# E1005: use of a moved binding

A `dat` argument, an assignment to another owner and a returned binding all
move ownership. ADR-0016 says the source then becomes `Moved` and has no
cleanup of its own, so the compiler rejects every later use, including a
second move. The error points at the later use.

## Example

```actus fails=E1005
verb finish(dat data: Buffer) {
    drop(data);
}

verb main() {
    erg data: Buffer = Buffer[4];
    finish(data: dat data);
    print(buffer_length(buffer: abs data));
}
```

A struct field takes ownership of a buffer, an arena, a struct or an enum even
when the field has no role, so the source is moved there as well:

```actus fails=E1005
struct Holder {
    held: Buffer,
}

verb main() {
    erg data: Buffer = Buffer[4];
    erg holder = Holder { held: data, };
    append(data, 1u8);
}
```

An enum payload takes ownership in the same way, so `Option`, `Result` and
user enums move a buffer or an arena into the new value. An `erg` parameter is
a new owner inside the callee, so a buffer or an arena handed to it is moved
too, with or without the explicit `erg` role:

```actus fails=E1005
verb main() {
    erg arena: Arena[64] = Arena[64]();
    erg held: Option[Arena[64]] = Option[Arena[64]].Some(arena);
    erg node = arena.place(value: 1);
}
```

```actus fails=E1005
verb keep(erg held: Buffer) {
}

verb main() {
    erg data: Buffer = Buffer[4];
    keep(held: data);
    append(data, 1u8);
}
```

A struct or an enum is moved by every one of these operations, whether it holds
a resource or only plain data (ADR-0124): a binding, an assignment, a struct
field initializer, an enum payload, an `erg` or `dat` argument and a return
all take the value away from the source. A read does not move it, so
`header.length`, a comparison and an `abs` argument can be repeated, but a
read after one of the moves above is the error:

```actus fails=E1005
struct Header {
    length: u16,
}

struct Frame {
    header: Header,
}

verb main() {
    erg header = Header { length: 4u16, };
    erg frame = Frame { header: header, };
    print(int: header.length);
}
```

```actus fails=E1005
enum Mode {
    Idle,
    Busy,
}

verb main() {
    erg mode = Mode.Idle;
    erg other = mode;
    erg again = mode;
}
```

A loop body is analysed once, but it runs again, so a value that is declared
before a loop and moved or dropped inside it is moved again by the next
iteration (ADR-0016). The error points at the move and says that it was made in
a previous iteration. It applies to `loop`, to `for` over a range or an array,
and to nested loops, and to every kind of move: a `dat` or `erg` argument, a
struct field or enum payload, an `erg` binding, a field of an owner and
`drop`:

```actus fails=E1005
verb finish(dat data: Buffer) {
    drop(data);
}

verb main() {
    erg data: Buffer = Buffer[4];
    for erg index in 0..3 {
        finish(data: dat data);
    }
}
```

```actus fails=E1005
verb finish(dat data: Buffer) {
    drop(data);
}

verb main() {
    erg data: Buffer = Buffer[4];
    erg count: Int = 0;
    loop {
        count += 1;
        if count > 3 {
            break;
        }
        if count > 1 {
            finish(data: dat data);
            continue;
        }
    }
}
```

## Fix

Use the value before it is moved. If the callee only reads the value, change
its parameter to `abs` so that the caller keeps ownership.

```actus compiles
verb finish(dat data: Buffer) {
    drop(data);
}

verb main() {
    erg data: Buffer = Buffer[4];
    print(buffer_length(buffer: abs data));
    finish(data: dat data);
}
```

In a loop, move the value on the path that leaves the loop, with `break` or
`return` right after the move, or declare the value inside the body so that
every iteration owns a new one. A value that is declared inside the loop is not
checked, because it does not exist in the next iteration:

```actus compiles
verb finish(dat data: Buffer) {
    drop(data);
}

verb main() {
    erg data: Buffer = Buffer[4];
    erg count: Int = 0;
    loop {
        count += 1;
        if count > 2 {
            finish(data: dat data);
            break;
        }
    }
    for erg index in 0..3 {
        erg fresh: Buffer = Buffer[4];
        finish(data: dat fresh);
    }
}
```

A struct or an enum that holds only plain data can declare `meta copy`, and
the copy is then written with `copy(value: abs x)`; the source stays usable
because nothing was moved:

```actus compiles
meta copy
struct Header {
    length: u16,
}

struct Frame {
    header: Header,
}

verb main() {
    erg header = Header { length: 4u16, };
    erg frame = Frame { header: copy(value: abs header), };
    print(int: header.length);
}
```
