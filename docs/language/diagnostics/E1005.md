# E1005: use of a moved binding

A `dat` argument, an assignment to another owner and a returned binding all
move ownership. ADR-0016 says the source then becomes `Moved` and has no
cleanup of its own, so the compiler rejects every later use, including a
second move. The error points at the later use.

## Example

```actus fails=E1005
verb finish(dat data: Buffer) {
    drop(data);
}

verb main() {
    erg data: Buffer = Buffer[4];
    finish(data: dat data);
    print(buffer_length(buffer: abs data));
}
```

A struct field takes ownership of a buffer, an arena, a struct or an enum even
when the field has no role, so the source is moved there as well:

```actus fails=E1005
struct Holder {
    held: Buffer,
}

verb main() {
    erg data: Buffer = Buffer[4];
    erg holder = Holder { held: data, };
    append(data, 1u8);
}
```

An enum payload takes ownership in the same way, so `Option`, `Result` and
user enums move a buffer or an arena into the new value. An `erg` parameter is
a new owner inside the callee, so a buffer or an arena handed to it is moved
too, with or without the explicit `erg` role:

```actus fails=E1005
verb main() {
    erg arena: Arena[64] = Arena[64]();
    erg held: Option[Arena[64]] = Option[Arena[64]].Some(arena);
    erg node = arena.place(value: 1);
}
```

```actus fails=E1005
verb keep(erg held: Buffer) {
}

verb main() {
    erg data: Buffer = Buffer[4];
    keep(held: data);
    append(data, 1u8);
}
```

## Fix

Use the value before it is moved. If the callee only reads the value, change
its parameter to `abs` so that the caller keeps ownership.

```actus compiles
verb finish(dat data: Buffer) {
    drop(data);
}

verb main() {
    erg data: Buffer = Buffer[4];
    print(buffer_length(buffer: abs data));
    finish(data: dat data);
}
```
